# ATLAS UI Kit — техническая дизайн-система Help Desk

Практическая работа № 5 по дисциплине «Техническое качество веб-интерфейса».

## Цель и исходная проблема

В стартовом проекте уже были HTML-разметка и базовая сетка, но не хватало завершённой системы тем, стилей и состояний компонентов. Повторение отдельных цветов и размеров в разных компонентах усложняет поддержку, поэтому интерфейс оформлен через три уровня CSS Custom Properties: **primitive → semantic → component**.

Задача: подготовить единый UI Kit для форм, списка обращений и административной панели Help Desk с доступными компонентами, системной/ручной темой и настраиваемой плотностью.

## Структура проекта

| Файл | Назначение |
|---|---|
| `index.html` | Семантическая демонстрационная страница и два выпадающих списка настроек |
| `css/tokens.css` | Палитра, типографика, отступы, семантические роли для двух тем и токены плотности |
| `css/components.css` | Разметка сетки и стили/состояния кнопок, контролов и уведомлений |
| `js/theme.js` | Логика темы и плотности с независимым сохранением настроек |
| `screenshots/` | Четыре скриншота для сдачи |
| `reference/` | Исходные PNG-ориентиры из архива преподавателя |

Не используются Bootstrap, Tailwind, готовые UI-библиотеки и CSS-фреймворки.

## Запуск

Из корневой папки проекта выполните:

```bash
python3 -m http.server 5500
```

На Windows также можно использовать `python -m http.server 5500`. Перейдите по адресу <http://localhost:5500/>. Проект статический и не требует сборки или установки пакетов.

После публикации в GitHub Pages ту же страницу можно открывать по публичному URL.

## Реализованные токены

1. **Primitive (примитивы)** — независимые значения палитры `--base-*`, шкалы `--space-1`…`--space-12`, размеров шрифта `--font-size-*`, радиусов `--radius-*` и начертания текста.
2. **Semantic (роли)** — `--color-page`, `--color-surface`, `--color-surface-subtle`, `--color-text`, `--color-text-muted`, `--color-border`, `--color-border-control`, `--color-primary`, `--color-link`, `--color-focus-ring`, роли `info/success/error/warning` и их фоновые подложки.
3. **Component (компонентные)** — `--button-bg-primary`, `--button-text-primary`, `--button-bg-secondary`, `--button-text-secondary`, `--control-bg`, `--control-text`, `--button-height`, `--control-height`, `--button-padding-inline`, `--control-padding-inline`, `--component-gap`, `--alert-padding`.

Три реальные цепочки значений (светлая тема):

| Уровень primitive | Уровень semantic | Уровень component | Реальное использование |
|---|---|---|---|
| `--base-blue-700` | `--color-primary` | `--button-bg-primary` | `.button--primary { background: var(--button-bg-primary); }` |
| `--base-white` | `--color-surface` | `--control-bg` | `.input, .select { background: var(--control-bg); }` |
| `--base-slate-950` | `--color-text` | `--control-text` | `.input, .select { color: var(--control-text); }` |

Переопределение `--color-primary` изменяет основную кнопку, логотип и палитровый образец. В `components.css` нет прямых HEX-цветов.

## Реализованные темы и настройки

- **Auto** — у элемента `<html>` нет `data-theme`; системный dark обрабатывается `@media (prefers-color-scheme: dark)`.
- **Light** — атрибут `data-theme="light"` принудительно сохраняет светлую палитру, даже если в ОС выбран тёмный режим.
- **Dark** — атрибут `data-theme="dark"` включает тёмную палитру независимо от ОС.
- Выбор темы сохраняется в `localStorage` по ключу `atlas-theme`. Если хранилище недоступно или значение неизвестно, используется `auto`.
- Плотность **Обычная / Компактная** меняется независимо от темы. Значение `normal` или `compact` сохраняется в `localStorage` по ключу `atlas-density`.
- Компактный режим задаёт `data-density="compact"` и переопределяет шесть компонентных токенов: `--button-height`, `--control-height`, `--button-padding-inline`, `--control-padding-inline`, `--component-gap` и `--alert-padding`.

## Компоненты и состояния

| Компонент | Что реализовано |
|---|---|
| Кнопка Primary | Default, Hover, Active, Focus-visible, Disabled |
| Кнопка Secondary | Default, Hover, Active, Focus-visible |
| Кнопка Ghost | Default, Hover, Active, Focus-visible, контраст в тёмной теме |
| Input / Select | Общая высота, отступы, цвета, placeholder, focus, disabled, invalid |
| Уведомления | Info, Success, Error, Warning; различимые заголовки, описание и символ |
| Демонстрация действия | Кнопка «Создать заявку» выводит текстовый статус через `aria-live="polite"` |

Для поля имени сохранён связанный `label`. Ошибочный email содержит `aria-invalid="true"` и `aria-describedby="email-error"`, а ниже выводится читаемый текст ошибки. Цвет не является единственным признаком предупреждения.

| Условие | Результат |
|---|---|
| Ширина 320 px | Пройдено: горизонтального скролла нет, длинное warning переносится |
| Ширина 375 px | Пройдено: горизонтального скролла нет |
| Ширина 768 px | Пройдено: горизонтального скролла нет |
| Ширина 1024 px | Пройдено: горизонтального скролла нет |
| Ширина 1440 px | Пройдено: горизонтального скролла нет |
| Tab и Shift+Tab | Сохраняется системный порядок фокуса; контур `:focus-visible` толщиной 3 px виден при навигации Tab |
| Auto при светлой/тёмной ОС | Пройдено: фон подстраивается под системную тему |
| Ручная Light при тёмной ОС | Пройдено: светлая тема имеет приоритет |
| Ручная Dark | Пройдено: устанавливаются тёмные роли |
| Независимое сохранение темы/плотности | Пройдено: проверка логики чтения/сохранения с имитацией `localStorage` и повторной инициализацией |
| Кнопки | Стили hover/active/disabled заданы отдельно, кнопка демонстрации реагирует на нажатие |
| Invalid email | Красная граница и текст связаны атрибутом `aria-describedby` |
| `--color-primary` | Тот же семантический токен используется в образце, логотипе и кнопке |
| Контраст | Вычислен по WCAG: основной текст ≥ 13.9:1, сообщение warning ≥ 6.3:1, границы контролов ≥ 3.7:1 на обеих темах |

Визуальная и адаптивная проверка проводилась в Chromium. Проверка JavaScript-сохранения отдельно выполнена с тестовым хранилищем: в среде создания проекта навигация браузера на `localhost` ограничена. Для окончательной сдачи полезно дополнительно проверить сохранение после F5 в собственном браузере на GitHub Pages.

## Ответы на вопросы самостоятельной части

**Почему плотность задаётся компонентными токенами?** Компактный режим должен менять размеры контролов, отступы и интервалы, а не базовую цветовую палитру. Компонентные токены позволяют переключать плотность в одном месте без дублирования правил `.button`, `.input` и `.alert`.

**Почему тёмная тема не должна хранить прямые цвета внутри `.button`?** При жёстких цветах в классах кнопок пришлось бы вручную исправлять каждую тему и каждое состояние. Семантические токены централизуют выбор цветов, поэтому изменение темы автоматически распространяется на компоненты.

## Публикация в GitHub Pages

1. Создайте публичный репозиторий на GitHub и загрузите файлы проекта в его корень (там должен быть `index.html`).
2. На GitHub выберите **Settings → Pages → Build and deployment → Deploy from a branch**.
3. Выберите ветку **main**, папку **/(root)** и нажмите **Save**.
4. В разделе Pages после завершения публикации появится ссылка вида `https://USERNAME.github.io/REPO/`.
5. Для сдачи отправьте ссылку на репозиторий и рабочий URL страницы, а также четыре скриншота.
